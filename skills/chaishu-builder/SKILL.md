# 拆书经验积累构建器（chaishu-builder）

## 一句话定义

这个技能的作用是：**把拆书结果中的精华提炼成可复用的创作知识，持续沉淀到项目知识库中**。每次拆完一本书，都会让人设库、剧情库、爽点库、节奏库、金手指库更丰富，形成自己的创作方法论积累。

## 核心流程

### 输入判断

| 情况 | 处理方式 |
|------|---------|
| 用户直接提供了拆书结果文件内容或路径 | 直接读取拆书结果文件 |
| 用户提供了书名，但没有拆书结果文件 | 调用 chaishu 技能进行拆书，生成拆书结果并保存 |
| 用户提供了书籍内容/章节正文，但没有拆书结果文件 | 调用 chaishu 技能进行拆书，生成拆书结果并保存 |
| 用户同时提供了书名和书籍内容 | 用书籍内容进行拆书，更准确 |

### Step 1: 获取拆书结果

#### 情况A：已有拆书结果文件
1. 检查用户提供的文件路径是否存在
2. 用 `file_read` 读取完整内容

#### 情况B：没有拆书结果文件，需要先生成
1. 检查是否有 `chaishu` 技能可用（在 Available Skills 中查找）
2. 如果有 `chaishu` 技能，加载该技能，调用其工作流程生成拆书结果
3. 如果没有 `chaishu` 技能，按照网文拆书的五大维度规则自行拆解：
   - **卖点与开篇**：分析黄金三章、书名简介钩子、前300-1000字、章末钩子类型
   - **人设体系**：主角欲望痛点、配角反派衬托、冲突来源
   - **节奏与情绪曲线**：爽点铺垫与释放、高潮密度、钩子设置
   - **大纲与故事结构**：主线情节、危机递进、模块化结构
   - **金手指体系**：金手指的设定、边界、升级频率、与主线的耦合
4. 将拆书结果保存到项目目录 `拆书/` 下，文件名格式为 **`拆书-{书名}.md`**

### Step 2: 解析拆书结果，提取五大维度

拆解拆书结果文件，提取以下信息：

#### 2.1 人设提取 → 追加到 `人设.md`
提取内容：
- **主角**：核心特征、欲望、痛点、性格标签、成长弧线
- **重要配角**：功能定位、性格特点、与主角关系
- **反派**：压迫力来源、动机、衬托作用
- **人设搭配逻辑**：为什么这样搭配效果好（如：高冷主角+话痨配角）
- **来源标注**：标注来自哪本书的拆书，方便追溯

#### 2.2 剧情提取 → 追加到 `剧情.md`
提取内容：
- **主线结构**：大主线是什么，分几卷/几个阶段
- **经典桥段/情节模块**：如"装逼打脸"、"英雄救美"、"秘境夺宝"等，归纳其结构和节奏
- **转折设计**：关键转折点，转折方式
- **冲突设计**：核心冲突来源（人与人的冲突、人与环境的冲突、人与自己的冲突）
- **来源标注**：标注来自哪本书的拆书

#### 2.3 爽点提取 → 追加到 `爽点.md`
提取内容：
- **爽点类型**：打脸爽、扮猪吃虎、逆袭、碾压、收集、升级、揭秘等
- **爽点密度**：平均多少章一个爽点
- **爽点结构**：铺垫（憋屈/压抑）→ 释放（爽）的节奏和比例
- **有效爽点清单**：列出书中效果最好的几类爽点及其写法
- **来源标注**：标注来自哪本书的拆书

#### 2.4 节奏提取 → 追加到 `节奏.md`
提取内容：
- **开篇节奏**：前三章的信息释放节奏（第1章抛什么、第2章抛什么）
- **章节节奏**：一章内的高潮点和钩子位置
- **情绪曲线**：章节/卷的起伏节奏（铺垫-高潮-回落-再铺垫）
- **钩子系统**：章末钩子类型（悬念钩、对话钩、事件钩、情绪钩），钩子频率
- **来源标注**：标注来自哪本书的拆书

#### 2.5 金手指提取 → 追加到 `金手指.md`
提取内容：
- **金手指设定**：具体是什么、来源、规则
- **金手指边界**：限制条件、使用代价、冷却机制
- **金手指升级路线**：如何逐步变强、升级节点
- **金手指与剧情耦合**：金手指如何驱动剧情，而不是让剧情失效
- **来源标注**：标注来自哪本书的拆书

### Step 3: 写入知识库文件

#### 写入格式规范

每个知识库文件采用以下结构追加内容：

```markdown
## [书籍名称] - 拆书积累

### 人设/剧情/爽点/节奏/金手指 内容

[具体内容，用结构化方式呈现]

---

```

#### 具体要求

1. **追加到文件末尾**：使用 `file_write` 的 `append` 操作，在文件末尾追加新内容
2. **分隔清晰**：每条记录以 `## 书名` 开头，以 `---` 分隔
3. **结构化呈现**：用列表、表格、分类等方式组织，不要纯段落
4. **可复用性**：提炼出的内容应该能直接用于指导自己的创作
5. **来源可追溯**：每条内容标注来源书名

### Step 4: 输出汇总报告

完成所有写入后，向用户输出一份汇总报告：

```
📚 拆书经验入库完成！

📖 书籍：《书名》
├── 👤 人设 → 已追加到 人设.md（提取了X条）
├── 📜 剧情 → 已追加到 剧情.md（提取了X条）
├── ⚡ 爽点 → 已追加到 爽点.md（提取了X条）
├── 🎵 节奏 → 已追加到 节奏.md（提取了X条）
└── 💎 金手指 → 已追加到 金手指.md（提取了X条）

💡 本次拆书积累的核心收获：
[列出3-5条最有价值的可复用经验]
```

## 重要规则

1. **不重复入库**：检查知识库文件中是否已有该书的拆书积累，如果已有则提示用户是否覆盖或追加
2. **不泛泛而谈**：提取的内容必须是具体、可操作的创作经验，不要写"角色塑造得好"这种空话，要写"角色通过XXX方式塑造"的具体方法
3. **保持结构化**：所有知识库条目必须结构化，方便日后检索和复用
4. **来源标注**：每条内容必须标注来源（书名+章节范围），方便后续追溯验证
5. **先读后写**：写入前先读取知识库文件现有内容，避免重复
6. **拆书文件不存在时**：如果用户指定的拆书文件不存在，提示用户并提供可用选项（用书名重新拆、提供书籍内容等）
7. **拆书结果文件路径**：默认在项目目录 `拆书/` 下查找

## 输出格式

最终输出为汇总报告（见 Step 4），告知用户哪些内容写入了哪个知识库文件。
