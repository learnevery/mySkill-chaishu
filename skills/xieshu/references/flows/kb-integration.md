# 拆书知识库联动（chaishu × xieshu）

xieshu 可与 chaishu 拆书技能沉淀的知识库联动：拆书产出**市场验证过**的创作范式，写书时直接取用，形成「拆 → 提炼 → 写」闭环。

**原则：知识库只是增强，不是依赖。** 无知识库时全部流程照旧，使用内置通用写作指南；有知识库时，凡库内有同赛道条目的，优先采用库内范式。

## 知识库位置与格式

Phase 0 按以下顺序检测（任一位置找到即视为知识库可用）：

1. 当前工作目录下的 `人设.md` / `剧情.md` / `爽点.md` / `节奏.md` / `金手指.md` / `范式.md`（chaishu CLI `kb add` 的默认入库位置）
2. `./知识库/` 目录下的同名文件

知识库格式（由 chaishu / chaishu-builder 维护，**xieshu 只读、从不写入**）：

- 每本书一个 `## [书名] - 拆书积累` 条目，以 `---` 分隔
- 内容为结构化列表/表格，典型字段：爽点类型与铺垫/释放比例、情绪曲线模板、人设搭配逻辑、金手指边界与升级频率、危机递进链、开篇公式、章末钩子类型统计

## 各阶段注入规则

| 阶段 | 读取 | 用法 |
|------|------|------|
| Phase 0 初始化 | 全部 | 检测知识库，统计积累规模（拆过几本书、哪些赛道），声明本次创作将套用库内范式 |
| Phase 1 Layer 1 | 剧情.md、爽点.md | Q1 题材选项将库内有同赛道积累的排前并标记📦；Q3 冲突选项优先纳入库内高频冲突类型 |
| Phase 2 规划 | 节奏.md、剧情.md、人设.md、金手指.md、范式.md | 大纲的情绪曲线与高潮密度参照库内模板；危机递进链、人设搭配逻辑、金手指边界从库内取；**每章规划的「爽点设计」「悬念钩子」两列从库内范式清单中选型**（无库时按内置指南自行设计） |
| Phase 3 逐章写作 | 爽点.md、范式.md | 写前分析时按大纲本章标注的爽点类型与钩子类型，读取库内对应条目的具体写法（铺垫→释放结构、钩子样式），落实到本章正文 |

## 大纲中的范式标注

接入知识库后，`01-大纲.md` 章节规划表的两列有明确来源：

- **爽点设计**列：填写本章部署的爽点类型及铺垫→释放安排。有知识库时，类型选自 `爽点.md` 的有效爽点清单，铺垫/释放比例参照库内拆解结论；无知识库时自行设计
- **悬念钩子**列：章末钩子类型。有知识库时优先选 `范式.md` 中该赛道高频钩子类型；无知识库时参考 [hook-techniques.md](../guides/hook-techniques.md)「悬念钩子十三式」

标注的作用：Phase 3 每章写前分析据此回查知识库取写法，保证「规划时选型、写作时执行」一致。

## 合规红线（与 chaishu 一致）

- 知识库存的是**写作机制、情绪模型、节奏范式**（骨架），不是情节、人名、桥段（血肉）
- 创作时**借鉴骨架，拒绝复制血肉**：不得照搬知识库中记录的具体情节、人物设定、专属名词
- 产出的大纲和正文不得与任何被拆书籍构成可识别的相似剧情链；发现写作产出滑向复述库内情节时，立即停下换用新的故事外壳
